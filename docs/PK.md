# PK（盲测对比）规范

目的：拿同一批装柜问题，让本方案和其他方案（人工 / 商业软件 / 其他算法）各自出方案，用**同一个独立校验器**打分，谁的数都能复现。

## 流程

1. **出题**：主持方准备问题文件（`docs/FORMAT.md` 的行格式，`C` 行给出可用柜型和相对运费，`R` 行可覆盖硬约束）。
   问题对所有参赛方相同；需要保密时只发问题文件，不发任何参考答案。
2. **答题**：每个参赛方对每个问题交一份方案，放在自己的目录 `DIR/<问题名>.json` 或 `DIR/<问题名>.csv`；
   可选 `DIR/<问题名>.time`（一行数字，求解耗时秒）。耗时由参赛方自报，主持方可以现场计时复核。
3. **评分**：
   ```
   python3 tools/pk.py --problems problems/ --plans 甲=dirA 乙=dirB [--ours-ms 2000] --md leaderboard.md --json pk.json
   ```
   `--ours-ms T` 现场跑本仓库内核（四种构造思路各 T 毫秒，取最好）作为参赛方 `ours`。

## 方案格式

- **JSON**：与内核输出相同（`docs/FORMAT.md`）。只用到每个柜的 `type` 和每个箱的 `id / x y z / dx dy dz`；
  重量、卸货站、易碎、危险品**一律以问题文件为准**，参赛方自报的属性不采信。箱号可以是 `<I 行 id>` 或 `<I 行 id>#<序号>`。
- **CSV**（给不方便出 JSON 的参赛方）：表头 `container,type,id,x,y,z,dx,dy,dz`，一行一箱，坐标单位 mm，
  原点为柜内前端左下角，x 沿柜长（x=0 柜底/前端，x=L 柜门），y 柜宽，z 高度；`container` 是参赛方自己的柜编号。

## 校验（全部是硬约束，任何一条不满足 = 该题方案"不可执行"）

| 检查 | 说明 |
|---|---|
| 箱子身份 | 每个 I 行恰好放 `数量` 个，不多不少，不能出现问题里没有的箱号 |
| 尺寸 / 方向 | `dx dy dz` 必须是该箱 `长宽高` 的一个排列；`摆放=1` 时高度必须是原高度（只能绕竖轴转），`摆放=2` 时不能转 |
| 柜型 | 只能用问题 `C` 行里有的柜型 |
| 越界 / 重叠 / 超重 | 同 `tools/verify.py` |
| 支撑 | 每个不在柜底的箱子，底面被下方箱顶支撑的比例 ≥ `min_support`（默认 0.75） |
| 先卸后装 | 卸货站序小的箱子不能被站序大的箱子在门方向挡住（`lifo=0` 可关闭） |
| 承重 / 易碎 | 每个箱子顶面直接承受的重量（上方每个箱子按接触面积比例分摊）≤ 顶部最大承重；易碎箱上不能压货 |
| 危险品 | 不同类别危险品沿柜长方向间距 ≥ `hazmat_sep`（默认 1000 mm） |

## 排行规则

1. 可执行的题数多者在前；
2. 同等可执行题数下，比较"共同可执行题"（可执行题数最多的那几家都可执行的题）上的**总运费**，低者在前；
3. 同时列出总柜数、平均体积装载率、总耗时，便于看"省在哪里、花了多少时间"。

运费按问题 `C` 行的相对运费计。真实运价不同，只需改 `C` 行重新评分，方案本身不用重算。

## 注意

- 拼柜（多票分配到多个柜）的 PK 同样适用：把一条线路的所有票写进一个问题文件，交整条线路的多柜方案即可；
  "同一票不拆柜"这条业务约束 `pk.py` 目前**不检查**（问题格式里没有票号字段），需要时用 `tools/consolidate.py` 输出里的 `shipments` 字段核对。
- 真实客户数据只在本地评测，排行榜只公开汇总数字。
